## Depth ladder (reversibility x precedent x blast radius, not line count)
- D0 Answer: questions, status. Read TASKS.md, answer, stop.
- D1 Execute: reversible local edits with a pattern. Do it, tests must pass.
- D2 Execute with lifecycle: new surface on known pattern. Design note + implement + test + docs + TASKS.md.
- D3 Design before code: no precedent, multi-session, or architecture. ADR to docs/DECISIONS.md, get approval, then stage. Never architect + migrate + build in one sitting.
- D4 Recommend and wait: push, deploy, credentials, schema, vendor, legal, product direction, anything irreversible. Ask ONCE with full context, execute only on explicit yes.

## Self-approval vs ask
- Self-approve (D1): bug fixes, feature code, tests, docs, refactors, security hardening, anything reversible that keeps tests green and health HEALTHY.
- Always ask first (D4): git push, any deploy, new dependency, schema/architecture change, credentials/secrets, vendor selection, anything touching auth/tenant isolation/app.py/site_data.py/public API.

## Hard invariants
- No ORM, ever. Raw SQL via `webstaffr/db.py` `get_connection()`, `?` placeholders, `DB_ERRORS` wrapper.
- Every SQL query hand-scoped to `tenant_id`. Missing scoping is a silent-in-production bug; log to TASKS.md.
- Composition root: `webstaffr/app.py` `create_app()` is the ONLY place routes register. New workers add a sibling router, never nested in `workers/angel/`.
- Migration parity: every logical schema change must exist in both SQLite (`webstaffr/migrations/`) and Postgres (`webstaffr/migrations/postgres_manual/`). Postgres additionally carries RLS migrations by design.
- CORS: browser-facing routes (`/chat`, `/intake*`, `/sites/*`, `/tenants/*`) get CORS; server-to-server (`/book`, `/webhooks/ghl`, `/retell/*`, `/integrations/*`, `/workflow-graph/*`) do not.
- Vercel is serverless: no held connections or persistent processes.
- Never fabricate ratings, reviews, testimonials, or credentials. Omit missing sections rather than fill.
- Credentials never requested in chat. Set via Vercel env var (Sensitive) or `.env` (gitignored); verify with a pass/fail script, never echo the value.
